# atcgen DSL 拡張設計案（Phase 6-A）

Phase 6-A 時点の設計案。第1〜2節の現状は設計時の Phase 4-B とコーパスを指す。ネストした `for` と `row` は Phase 6-B、整数同士の条件分岐は Phase 6-C で実装済み。ASCII 文字比較と固定長文字列・グリッドは Phase 6-D で実装済み。第6節の文字に関する設計と第7節の ABC400-D 例を正式仕様に反映した。第10節の高度な生成方法を [Phase 6-E-Aの設計](ADVANCED_GENERATION_CONSTRAINTS.md) で具体化し、そのU1（除外付き重複なし一括初期化）だけをPhase 6-E-Bで実装済み。他の高度な新構文は未実装。第1〜2節および比較表は設計時点の記録として残す。 [現行 DSL 仕様](DSL_SPEC.md)

## 1. 現行 DSL の制限

- `generate` は実行順に `i64` スカラーと一次元配列を生成する。宣言はトップレベルに置き、要素の初期化は一度だけ。配列添字は1始まり。
- `input` は生成完了後に値を読み、参照列を1行ずつ出力する。裸の配列名は配列全体を同じ行に展開する。文字や部分配列を出力する構文はない。
- 両ブロックの `for` は1段。生成側の本体は要素初期化の列、出力側の本体は行の列である。比較や条件分岐はない。
- Parser は行単位で構文を読み、Validator はトップレベルの宣言順とループ変数1個を使って参照を束縛する。Generator は添字と初期化状態を実行時に検査し、Output は全行の値とバイト数を確定してから整形する。 [Parser](../src/parser.rs) · [AST](../src/ast.rs) · [Validator](../src/validation.rs) · [Generator](../src/generator.rs) · [Output](../src/output.rs)

## 3. 設計原則

1. `generate` は宣言と初期化をソース順に実行する。宣言済みの配列・文字列セルは、先行する文や反復で初期化された時点から読める。
2. `input` は生成完了時の値を読み取り専用で使用する。分岐や同じ値の再出力による乱数消費はない。
3. 宣言、初期化、参照は構文と束縛で区別する。大きさと添字は `i64` の式とし、参照は1始まりとする。
4. 名前と型は全経路で静的に検証する。添字、初期化状態、算術、容量は実行した経路で検証する。公式問題固有の制約は生成器の構成で保証し、コーパスのチェッカーで照合する。
5. 出力全体の検証・整形を終えてから標準出力に書く。DSL の失敗時の標準出力は0バイト。
6. 同じ構文を異なる問題で再利用する。自動変換では、入力行、繰り返し、種別ごとの書式をそれぞれ明示的に対応付けられる形を選ぶ。

## 4. 構文候補の比較

### 文字列とグリッド

| 方式 | 記述と実装の比較 |
| --- | --- |
| `S : string[W]` と `G[H] : string[W]` | 宣言時に寸法が決まり、各文字を同じ初期化規則で扱える。1行をそのまま出力できる。ASCII では文字セルを1バイトで表せる。 |
| 独立した文字配列と結合操作 | 文字配列の表示が空白区切りか連結かを各出力位置で指定する必要がある。結合演算、値の長さ、出力型の追加が必要。 |
| グリッド専用の生成構文 | 長方形のグリッドは短く書ける。単独の文字列と別の生成規則が必要で、指定座標の依存関係は一般の初期化規則で表現できる。 |

文字列を固定長の文字セル列として扱う案を採る。単独の文字列と文字列配列で記憶表現を共有し、セルの初期化と文字列単位の出力を組み合わせる。

### 可変長の行

| 方式 | 構文と読みやすさ | 実装負担と既存 DSL との整合性 |
| --- | --- | --- |
| 明示的な `row { … }` | 行の始点・終点が見える。ブロック内では既存の `for` を使い、固定の値と可変個の値を同じ行に置ける。 | 行の開始・終了と行内モードを追加する。通常の `for` と参照列の構文を再利用できる。 |
| 行内専用 `for`（例 `N (for j in 1..=N: A[j])`） | 短い1行には向く。複数要素や条件付きの展開が重なると長くなり、改行の規則が必要。 | 反復を値列の式として別途解析・束縛する。現行の行内参照と空白区切りの規則に新しい文法が加わる。 |
| スライスの行内展開（例 `A[lo..=hi]`） | 連続区間の行は短い。複数配列から交互に取る値や非連続の添字には別の手段が必要。 | 添字演算に区間を追加し、空区間、境界、各要素の初期化を規定する。生成側のネストは別途必要。 |

`row` を推奨する。改行の境界が局所的で、生成側と出力側の反復が対応する。下三角行列とケースごとの可変長配列は、一次元配列を平坦化して記述できる。

### 条件分岐

| 方式 | 比較 |
| --- | --- |
| 両ブロックで `if` / `else` | 同じ生成済みの種別を条件にして、初期化したフィールドだけを出力できる。二分岐と比較演算で公式の種別ごとの書式を直接写せる。 |
| `match`・種別付きレコード | 種別の多い問題では見通しがよい。パターンやレコードの型、網羅性の規則が増える。ABC420-E では種別2・3が同じ行幅で、二分岐で足りる。 |
| 0回または1回の `for` による代用 | 現行で一部を表現できる。範囲式から分岐の意図を復元しにくく、生成と出力が同じ経路を選ぶことも読み取りづらい。 |

比較を1つ含む条件式と `if` / `else` を採る。複数条件は入れ子で表現する。

## 5. 推奨構文

| 構文例 | 意味 |
| --- | --- |
| `S : string[L]` | 長さ `L` の未初期化文字列を宣言。 |
| `G[H] : string[W]` | 幅 `W` の文字列を `H` 個宣言。 `G[i]` は行文字列、`G[i][j]` はその文字。 |
| `G[i][j] in ".#"` | 候補文字集合から1文字を抽選してセルを初期化。 |
| `G[i][j] = '.'` | 指定文字でセルを初期化。初期化済みの別セルを右辺から読むこともできる。 |
| `for i in 1..=N { … }` | 既存の反復をネスト可能にする。 |
| `row { … }` | 内部の参照列と反復を同じ1行に展開。 |
| `if Kind[i] == 1 { … } else { … }` | 実行時に選んだ一方の本体を評価。ブロックのヘッダーは次節の改行規則に従う。 |

## 6. EBNF と意味論

### 6.1 文法差分

以下の規則は同名の Phase 4-B 規則を置き換える。ここにない下位規則は現行仕様を参照する。`scalar-generate` と `array-declare` は従来どおり整数用で、規則自体に改行を含まない。`escape` の EBNF 終端記号にあるバックスラッシュは1バイトを表す。

```ebnf
generate-block   = "generate", "{", line-end,
                   { blank-line | decl | gen-stmt }, close ;
decl             = ( scalar-generate | array-declare | string-declare ), line-end ;
string-declare   = name, [ subscript ], ":", "string", subscript ;
gen-stmt         = ( element-init | char-init ), line-end | gen-for | gen-if ;
element-init     = indexed-ref, "in", ( range | alphabet ) ;
char-init        = indexed-ref, "=", expression ;
gen-for          = for-header, gen-body, close ;
gen-body         = { blank-line | gen-stmt } ;
gen-if           = if-header, gen-body, ( close | else-header, gen-body, close ) ;

input-block      = "input", "{", line-end, input-body, close ;
input-body       = { blank-line | output-line | input-for | input-if | row-block } ;
input-for        = for-header, input-body, close ;
input-if         = if-header, input-body, ( close | else-header, input-body, close ) ;
row-block        = "row", "{", line-end, row-body, close ;
row-body         = { blank-line | output-line | row-for | row-if } ;
row-for          = for-header, row-body, close ;
row-if           = if-header, row-body, ( close | else-header, row-body, close ) ;

if-header        = "if", condition, "{", line-end ;
else-header      = "}", "else", "{", line-end ;
close            = "}", line-end ;
condition        = expression, comparator, expression ;
comparator       = "==" | "!=" | "<=" | ">=" | "<" | ">" ;

output-ref       = reference ;
reference        = name, [ subscript, [ subscript ] ] ;
indexed-ref      = name, subscript, [ subscript ] ;
primary          = digits | reference | char-literal | "(", expression, ")" ;
char-literal     = "'", ( literal-byte | escape ), "'" ;
alphabet         = '"', alphabet-byte, { alphabet-byte }, '"' ;
alphabet-byte    = set-byte | escape ;
escape           = "\", ( "\" | "'" | '"' ) ;
```

- `literal-byte` と `set-byte` は ASCII `0x21..=0x7E` のうち、バックスラッシュとそれぞれの囲み文字（単引用符、二重引用符）を除く。エスケープは直後の記号1バイトを表す。空白、制御文字、非ASCII文字、未対応のエスケープは構文エラー。復号後の候補文字集合は非空かつ重複なしとする。重複は静的エラー。
- `if` は文頭の独立した語と末尾の引用外の `{` がある場合、`row` は行のトークン列が `row` と `{` の場合にヘッダーとして解釈する。`else` は対応する `if` 本体の閉じ波括弧と同じ行に置く。`string` は型注釈位置で認識する。いずれも文脈キーワードで、例えば従来の `if row else` という参照列は有効。`for` の予約語と水平空白の規則は現行どおり。
- 比較演算子は最長一致。比較は条件位置に1つだけ置く。整数演算の括弧は使える。比較結果は条件専用の真偽値で、数値化、変数への保存、連鎖比較、論理演算は文法に含めない。

### 6.2 型と文字セルの初期化

| 参照対象 | 参照形 | 値と用途 |
| --- | --- | --- |
| 整数スカラー・整数配列 | `N`、`A[i]` | `Int`。整数式・比較・出力が可能。配列全体 `A` は出力時に整数列として展開。 |
| 文字列 | `S`、`G[i]` | `String`。初期化済みの全セルを連結し、1トークンとして出力。 |
| 文字セル | `S[j]`、`G[i][j]` | `Char`。セルの初期化、文字の比較、単一トークンとしての出力に使う。 |
| 文字列配列全体 | `G` | 出力時に添字順の文字列トークン列として同じ行に展開。行ごとの出力は `for` の本体に `G[i]` を置く。 |

- `string[L]` は長さを宣言時に確定する。文字列配列は共通幅を持つ。個数と長さは正の整数とし、個数がある場合は個数から長さの順に1回ずつ評価する。文字セルは初めすべて未初期化。整数配列と同様、読み出した分だけ初期化が必要で、文字列全体の出力には全セルの初期化が必要。
- Validator は形と添字数から参照を束縛する。参照先、添字は外側から左から右に解決し、実行時には各添字を評価した直後に境界を検査する。算術、添字、長さ、値域、ループ範囲は `Int` を要求する。文字と整数の暗黙変換、文字列全体の算術・比較、文字列配列への整数要素の格納は型エラー。
- `in range` は整数の初期化、`in alphabet` は文字セルの初期化。`=` は文字セルを `Char` の式で初期化する。初期化は対象の添字、初期化状態、右辺の順に検査し、成功時に1セルへ書く。 `=` は上書きに使えない。
- 文字の参照は1バイトを返す。引用符はソースの表記であり、出力には実際のバイトを使う。ASCII の非空白文字に絞ることで、従来のスペース区切りと行境界を共有できる。

### 6.3 スコープ、反復、分岐

- トップレベルの宣言だけが生成値の名前を作る。`for` と `if` の内部では宣言済みの配列・文字セルを初期化する。ループ変数は `Int` で読み取り専用。本体とその子ブロックから見え、自身のヘッダーや終了後からは見えない。裸の参照としての直接出力は現行どおり禁止する。
- トップレベルの宣言名とループ変数の衝突は両ブロックで検出する。内側のループは外側の有効なループ変数と同名にできない。兄弟ループや排他的な枝では名前を再利用できる。ブロックを抜けるとループ変数の束縛だけを破棄し、初期化した要素は値として残る。
- 各 `for` の入口で下限と上限を1回、左から右へ評価する。範囲は従来どおり昇順。内側の `for` に再び入るたびに、外側の変数とその時点の値で範囲を評価する。空範囲では本体を実行しない。
- `if` は左辺、右辺の順に読んで比較を1回評価する。整数同士は6演算子、文字同士は `==` と `!=` が使える。真なら前半、偽なら `else` の本体を実行する。`else` を省略した偽分岐は文・行・値を生成しない。静的な名前解決と型検査は両枝と空範囲の本体にも適用する。
- `generate` と `input` が同じ初期化済み要素を同じ添字で比較すれば、単一初期化のため結果は一致する。分岐間の初期化データフロー解析や暗黙の分岐の対応付けは前提にしない。選んだ経路で未初期化要素を読んだ場合と、別の反復や選んだ経路が同じセルを二重初期化した場合は実行時エラー。

### 6.4 改行と出力

- 通常の `input`、行ブロック外の `for` と `if` の本体では、参照列1行と明示的な空行1行がそれぞれ1個の LF で終わる。選ばなかった枝と0回反復は0行。
- `row` に入ると1行を開始する。行内の参照列は左から右へトークンを追加し、ソース上の行末は出力しない。行内の空行は無視する。行内の `for`、`if` はこの規則を継承する。 `row` の中に別の `row` は置けない。
- トークンの間は ASCII スペース1個。トークンの有無にかかわらず `row` の終了時に LF を1個出す。空範囲の行内ループだけを含む `row` は1空行。 `row` を含む外側のループが0回なら0行。行頭・行末には区切りを置かない。
- 生成値と選択済みの行を検証してから整形する。検証時に、文字列の全セル初期化、出力トークン数、区切りと LF を含むバイト数を確認する。同じ生成値を使って整形するため、整形時に分岐の再実行や乱数の消費はない。

### 6.5 上限、エラー、再現性

| 対象 | 上限の提案と計数 |
| --- | --- |
| 整数配列・生成整数 | 現行の個別・総容量および生成整数数の1,000,000をそれぞれ維持。 |
| 文字セル | 文字列の長さ、文字列配列の個数×長さ、全宣言の文字セルの合計をそれぞれ最大1,000,000とする。未初期化分を含めて確保前に計上する。文字は1セル1回だけ初期化できるため、初期化数にも同じ上限が効く。 |
| 反復回数 | `for` への進入1回につき従来どおり最大1,000,000回。空本体にも適用する。 |
| 実行量 | 当該ブロックの AST にネストした `for`、`row`、`if` のいずれかがある場合、`generate` と `input` を別々に最大10,000,000単位で計数。実行する文（制御ヘッダー、実際に出す通常の空行を含む）に1、ループ反復ごとに1を加える。範囲を検証した後、本体に入る前にその進入分の反復数を計上する。行内で無視する空行と未選択の枝は0。 |
| ネスト | 外側の `generate` / `input` を除き、開いている `for`、`if`、`row` は合計32段まで。`else` は対応する `if` と同じ深さ。式は従来の128段。添字参照の第1、第2添字の式に入る深さはそれぞれ参照元から1段、2段。宣言の個数・長さの式はそれぞれ深さ0。 |
| 出力 | 1ケースにつき最大1,000,000トークン、最大8 MiB。整数・文字・文字列を各1トークンと数え、配列全体は展開後のトークン数、同一値は出現ごとに数える。出力が文字列でも長さ分の全バイトを計上する。 |

- 上限ちょうどは有効。範囲幅・寸法の積・合計は検査付き演算または十分広い型で計算し、上限と符号を確認してから確保する。式評価のオーバーフローは現行どおりエラー。
- 診断は従来の1始まりの行・UTF-8 バイト列位置を使う。字句・ネスト上限の違反は該当トークン、名前衝突は宣言名、型不一致は対象の参照・演算子、添字超過は該当添字、未初期化は参照、二重初期化は初期化先を指す。容量超過は寸法式、反復上限は範囲上限、実行量超過は加算元の文またはループ範囲、出力上限は参照または LF を確定する行を指す。文字列の全体読みに失敗した場合は最初の未初期化セルの添字を示す。
- 整数抽選、区間幅1の乱数消費、SplitMix64 は現行と同じ。文字の抽選は復号後の記載順を保った集合に対し、既存の棄却抽選で添字を1つ選ぶ。候補が1文字でも乱数を消費する。`=` による文字の初期化、条件評価、出力は消費しない。選ばれた経路で実行した抽選だけが順に乱数を消費する。
- Phase 4-B で成功するソースは、同じ seed で同じ出力バイト列を得る。文脈キーワード、通常行・通常ループの規則、整数のみの上限の意味を保ち、追加の実行量上限は新しい制御構造を使うブロックに適用する。新しいソースへ書き換えた場合は、実行された抽選の順序と回数に従って出力が変わり得る。現行の CLI と `generate(source, seed)` の呼び出し方を維持する。
- 構文、静的検証、生成、出力前検証で失敗した場合は標準出力0バイトとする。成功後に出力先への書き込み自体が失敗した場合は、現行と同様に出力先が受け取ったバイトがあり得る。

## 7. 実問題の記述例

ABC370-B と ABC482-G の例は Phase 6-B、ABC420-E の例は Phase 6-C で実行できる。ABC400-D の例も Phase 6-D で実行できる。公式入力制約は各問題のメタデータと既存チェッカーに基づき、生成順と範囲から確認する。ABC400-D の専用チェッカーも Phase 6-D で追加済み。現在の分類は `supported / representative`。

### ABC400-D — 文字グリッド

```text
generate {
    H in 1..=1000
    W in (1+1/H)..=1000
    First in 1..=H*W
    Distance in 1..=(H*W-1)
    Last in ((First+Distance-1)%(H*W)+1)..=((First+Distance-1)%(H*W)+1)
    A in ((First-1)/W+1)..=((First-1)/W+1)
    B in ((First-1)%W+1)..=((First-1)%W+1)
    C in ((Last-1)/W+1)..=((Last-1)/W+1)
    D in ((Last-1)%W+1)..=((Last-1)%W+1)
    G[H] : string[W]
    for i in 1..=H {
        for j in 1..=W {
            if (i-1)*W+j == First {
                G[i][j] = '.'
            } else {
                if (i-1)*W+j == Last {
                    G[i][j] = '.'
                } else {
                    G[i][j] in ".#"
                }
            }
        }
    }
}

input {
    H W
    for i in 1..=H {
        G[i]
    }
    A B C D
}
```

`H=1` のときだけ `W` の下限を2にし、グリッド内に2マス以上を確保する。`Last` は1始まりの位置を非ゼロ距離だけ循環させた位置なので `First` と異なる。商と剰余で両方の座標がグリッド内に収まる。すべてのセルを行ごとに1回初期化し、指定した2マスには道を置く。それ以外は各セルで抽選する。最大寸法でも文字セルは1,000,000、実行量は生成側で約400万単位、出力は約1 MBで上限内。 [入力制約](../corpus/atcoder/abc400/d/problem.toml)

### ABC370-B — 下三角行列

```text
generate {
    N in 1..=100
    A[N*(N+1)/2]
    for i in 1..=N {
        for j in 1..=i {
            A[i*(i-1)/2+j] in 1..=N
        }
    }
}

input {
    N
    for i in 1..=N {
        row {
            for j in 1..=i {
                A[i*(i-1)/2+j]
            }
        }
    }
}
```

第 `i` 行の先頭前には `i*(i-1)/2` 要素ある。生成と出力で同じ添字を使うため、全セルを重複なく初期化し、各行が正確に `i` 整数になる。公式上限の `N=100` で 5050 セル。 `N=4` なら、ヘッダーに続いて幅1、2、3、4の4行を出す。 [入力制約](../corpus/atcoder/abc370/b/problem.toml)

### ABC420-E — 種別が混在するクエリ

```text
generate {
    N in 2..=65
    Q in 1..=(N-1)
    Kind[Q]
    U[Q]
    V[Q]
    for i in 1..=Q {
        Kind[i] in 1..=3
        if Kind[i] == 1 {
            U[i] in 1..=i
            V[i] in (i+1)..=(i+1)
        } else {
            V[i] in 1..=N
        }
    }
}

input {
    N Q
    for i in 1..=Q {
        if Kind[i] == 1 {
            Kind[i] U[i] V[i]
        } else {
            Kind[i] V[i]
        }
    }
}
```

種類1の端点は `1 ≤ U[i] ≤ i < V[i]=i+1 ≤ N`。各追加辺の大きい端点が異なるので重複しない。種類2・3は公式の書式どおり種類と頂点の2整数で、未初期化の `U[i]` を読まない。種類は各反復で抽選するため、3種のクエリをどの位置にも置ける。辺の形と規模に制限があり、種類3が一度も現れない入力も公式制約内である。 [入力制約](../corpus/atcoder/abc420/e/problem.toml)

### ABC482-G — 変動するケース数とケース内の長さ

```text
generate {
    T in 1..=10
    MaxN in 15..=15
    MaxM in (MaxN*(MaxN-1)/2)..=(MaxN*(MaxN-1)/2)
    N[T]
    M[T]
    First[T]
    A[T*MaxN]
    U[T*MaxM]
    V[T*MaxM]
    for t in 1..=T {
        N[t] in 2..=MaxN
        M[t] in 1..=(N[t]*(N[t]-1)/2)
        First[t] in 1..=(N[t]*(N[t]-1)/2-M[t]+1)
        for i in 1..=N[t] {
            A[(t-1)*MaxN+i] in 1..=(N[t]-1)
        }
        for v in 2..=N[t] {
            for u in 1..v {
                U[(t-1)*MaxM+(v-1)*(v-2)/2+u] in u..=u
                V[(t-1)*MaxM+(v-1)*(v-2)/2+u] in v..=v
            }
        }
    }
}

input {
    T
    for t in 1..=T {
        N[t] M[t]
        row {
            for i in 1..=N[t] {
                A[(t-1)*MaxN+i]
            }
        }
        for e in First[t]..(First[t]+M[t]) {
            U[(t-1)*MaxM+e] V[(t-1)*MaxM+e]
        }
    }
}
```

各ケースに固定幅の区画を確保し、そのケースの範囲だけを読み書きする。候補辺は `1 ≤ u < v ≤ N[t]` の全組を大きい端点、次に小さい端点の順に格納する。そこから連続する `M[t]` 辺を選ぶので、行数と一意性を保証し、閉路を含むグラフも生成できる。`N[t] ≤ 15` と `Aᵢ ≤ N[t]−1` より、各ケースの `sum(A) ≤ 210`。全体は `Σ(sum(A)³) ≤ 10×210³ = 92610000 ≤ 500³`、`ΣM ≤ 10×105 = 1050 ≤ 200000`。候補辺の連続区間に限ることと、公式上限より小さい `N` が制限として残る。 [入力制約](../corpus/atcoder/abc482/g/problem.toml)

### 比較と自動変換

行数は空行を除いたソース行で比較する。制約の充足根拠は各例に示した。表の実装負担は必要な DSL 機能の範囲を指す。

| 問題 | 現行 → 提案の行数 | 固定値・手動列挙と多様性 | 実装負担 | 入力形式からの変換 |
| --- | --- | --- | --- | --- |
| ABC400-D | 生成器なし → 32 | 行数・列数・端点を抽選。公式の文字集合と端点の道だけを固定。 | 文字型、ネスト、分岐が必要。 | `H` 行の文字列を型と反復に対応付ける。端点を固定する生成順は制約から組み立てる。 |
| ABC370-B | 26 → 19 | 行の手動列挙が消え、公式上限まで各セルを抽選できる。 | ネストと `row`。 | 行幅 `i` を内側のループ、1行の区切りを `row` に対応付ける。平坦化の添字は行長の累積から得る。 |
| ABC420-E | 31 → 26 | 種別の順序と最終行を固定する必要がなくなる。一意性のため、追加辺の大きい端点を反復番号から決める。 | 分岐と部分初期化の検証。既存の1段ループで足りる。 | 種別ごとのフィールド列を `input` の枝に写し、`generate` の同じ枝で必要フィールドだけを初期化する。 |
| ABC482-G | 44 → 39 | `T` と各ケースの長さが可変。区画の上限とグラフの構成は固定。辺の個数・区間・値を抽選する。 | ネストと `row`。ケース専用型や制約ソルバーは不要。 | ケース本体を1つのループに写す。配列の区画と総和を守る値域は生成方針として選ぶ。 |

問題文の自動変換では、まず出力構造を行、反復、種別の木として取り出せる。平坦化、辺の重複防止、集計上限からの範囲選択は生成側の別の判断で、書式だけから推定できない。自動生成した例も公式制約の根拠とチェッカーで照合する。

## 8. Validator と Generator への影響

| モジュール | 変更案 |
| --- | --- |
| Parser / AST | 行単位の字句処理を維持し、深さ上限付きで本体を再帰的に読む。`GenerateStmt::For` は要素初期化だけの列から生成文の列へ、通常の `InputStmt::For` は行だけの列から出力文の列へ拡張する。`If` に条件と両本体、`RowBlock` に行内の文列を持たせる。行内用の文の種類を限定して `row` の入れ子を構文段階で拒否する。文字列宣言、文字セル初期化、文字リテラルと比較演算子に診断位置を持たせる。 |
| Validator | トップレベル名の登録と宣言順の検査を維持し、再帰的にループ名を集める。本体の束縛にはループ変数のスタックを持ち、`LoopIndex` をスタック位置付きにする。出力用参照と式用参照を、添字数、宣言の形、値の型で確定する。両枝で型を検査し、生成先が実行時に同じセルを指すかどうかは実行時の検査に渡す。 |
| Generator | 逐次実行に本体の再帰とループ値スタックを追加する。比較を読み取り専用の評価器に置き、出力前検証と共有する。文字列は共通幅と連続したセル列で保持できる。文字に使わないバイトを未初期化の指標にすれば、行ごとに別の確保は不要。セル初期化の前に添字・重複・容量を検査し、文字の抽選に既存サンプラーを使う。 |
| Output | 現行の検証済み値と行末の保持を、整数・文字・借用した検証済み文字列のトークン列へ拡張する。通常行と `row` は同じトークン追加処理を使い、異なる位置で行を閉じる。出力前検証が実行した分岐・反復の結果を保持するため、整形が判断を繰り返す必要はない。 |
| ライブラリ / CLI | 構文解析、束縛、生成、出力前検証、整形、書き込みの順を維持する。DSL エラーで書き込み段階へ進まない。 |

実装時の主な検証点は、深い本体の構文エラーの位置、2添字の左から右への検査、行内と行外の LF の計数、同じ種別を利用した分岐の再現性。整数のみの既存生成器は、実装前の14 seed の出力と実装後の結果をバイト比較する。制約チェッカー通過だけでは、既存の乱数割当や空行の変化を検出できない。

## 9. 実装順序

ネストと行の境界から着手する。これで2問を直ちに改善でき、分岐とグリッドが利用する本体の解析、スコープ、実行量の計数を先に用意できる。文字セルの規則が決まるまでの分岐は整数に絞る。

| 段階 | 変更モジュール | 必要なテスト | コーパスで確認する改善 |
| --- | --- | --- | --- |
| **6-B — ネストした `for` と `row`** | Parser、AST、Validator、Generator、Output | 内側の範囲が外側の変数を読む、兄弟の同名は可・外側との衝突はエラー、空の `row` は LF 1個、0回の外側ループは0行、行内の区切り・重複初期化・深さと実行量の境界。 | ABC370-B で `N=1,100` と中間値を検証。ABC482-G で `T=1,10` と異なるケース規模を検証し、両方の集計制約を既存チェッカーで確認。 |
| **6-C — 整数の条件分岐** | Parser、AST、Validator、Generator の評価器、Output | 6比較演算子、文脈キーワード、選ばれない枝の静的エラーと実行時評価の省略、部分初期化、同じ種別での枝一致、`row` 内の分岐、後半に失敗したときの空の標準出力。 | ABC420-E で辺追加が種類2・3の間に現れる入力、種類1のない入力、公式制約に反する辺の重複をチェッカーが拒否することを確認。 |
| **6-D — ASCII 文字列とグリッド** | Parser、AST、Validator、Generator、Output。コーパスにチェッカーを追加。 | 引用とエスケープ、空・重複・非ASCIIの候補、文字と整数の型不一致、文字比較、寸法・容量・添字の境界、部分初期化の文字列出力、固定セルの抽選なし、幅1の候補の乱数消費、出力バイト上限。 | ABC400-D の寸法・行長・文字集合・座標範囲・座標の相違・両端セルが道であることをチェック。最小の横/縦グリッドと最大寸法のケースを確認してから status を再評価。 |

各段階で、既存の単体・CLI テストとコーパスを回す。提案例の検証では、寸法・件数の最小値と最大値を固定した例も用意し、有限の seed に境界値の出現を任せない。

## 10. 保留する拡張と理由

| 候補 | 現行または提案でできることと、再検討の条件 |
| --- | --- |
| 重複なし抽選・順列 | 剰余列や添字から値を作れば一意性は保証できる。ABC355-B と ABC300-A で値の組・順序を広げるなら、範囲から重複なく選ぶ共通機能が最初の候補。全域を選ぶ場合を順列として扱えばよく、順列専用構文は保留する。ABC300-A では既知の1値を除いた抽選も必要。 |
| 指定要素の固定・整列配列 | 整数の固定値は幅1の範囲で初期化できる。提案の分岐で他の位置と値域を分けられる。狭義昇順は前の値に1を足した下限と、残りの要素分を引いた上限で生成できる。固定・整列専用の修飾子は保留する。 |
| 木・単純グラフ | 番号の小さい親を選ぶ木、全候補辺の一部を選ぶ単純グラフは構成できる。任意ラベルの木、任意の辺集合、密度や次数の狙いが必要になったとき、まず順列や重複なし抽選から組み立てられる範囲を確認する。 |
| 配列・ケース間の総和 | このコーパスでは値域による保守的な配分が使える。各ケースや要素に残りの予算を順次割り当てる方法は、累積値を別配列に単一初期化する形でも検討できる。集計境界を狙う複数の問題がそろった段階で、集計関数または予算付きの抽選を比較する。 |
| 多次元・可変長配列、レコード、スライス | 下三角行列とケース列は一次元配列、文字グリッドは幅を共有する文字列配列で表現できる。平坦化で著しく読みにくい形式や容量の浪費が続く場合に再検討する。 |
| Unicode、可変長文字列、文字列演算 | 今回の対象は非空白 ASCII の固定長トークン。文字数とバイト数が異なる入力、または長さを生成後に変える入力が分析対象に入るまで保留する。 |
| 論理演算、関数、制約言語・汎用ソルバー | 今回の分岐は比較一つと入れ子で記述できる。式の再利用や集計の需要をコーパスで測り、逐次実行と seed の消費順を追える機能から検討する。 |

### レビューで確認する点

- 実行量の1,000万単位とネスト32段は暫定値。最大グリッドと深い制御構造の時間・メモリを実測し、式の評価コストも別途数える必要があるか判断する。既存ソースとの互換性のため、実行量上限の適用条件が構文に依存する点もレビューする。
- 文字初期化の `=` は抽選を消費しない。幅1の整数範囲と文字集合は抽選を消費するため、表記から期待される seed の挙動が分かりやすいか確認する。
- 生成・出力で分岐条件を書く場所が二つある。条件の食い違いは実行時の未初期化エラーやコーパス検証に現れることがある。自動変換では同じ入力形式の記述から両方の条件を組み立てる。
