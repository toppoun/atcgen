# 高度な生成制約の設計（Phase 6-E-A）

本書は Phase 6-D 完了時点の実装・全10問のコーパスを調査した設計案である。**新構文はすべて未実装**であり、[現行仕様](DSL_SPEC.md)、実装、テスト、生成器、メタデータ、チェッカーは変更しない。[拡張設計案の第10節](DSL_EXTENSIONS.md#10-保留する拡張と理由)を具体化する。旧設計案の第1〜2節は Phase 6-A 時点の記録なので、現在の対応状況には下記の調査結果を使う。

最初に実装する機能として、**宣言済み整数配列の、除外指定付き重複なし一括初期化**を推奨する。

```text
A[N]
A in unique(1..=200) except(B)
```

`B` は全要素が初期化済みの別の整数配列。`except` は省略可能で、`except(A+B)` のような既知の整数式も指定できる。宣言と初期化を分け、対象の全セルが未初期化であることを要求する。初版では候補範囲幅を1,000,000以下に限定し、昇順の候補列に部分 Fisher–Yates を適用する。対象4問の具体例は第5節、詳細な契約と実装計画は第9〜10節に示す。

### restricted 6問の制限の内訳

1. **ABC355-B：構造の制限。** `Offset in 0..=199` を選び、通し番号 `k=0..N+M-1` の値を `(37*k+Offset)%200+1` とする。`gcd(37,200)=1`、`N+M≤200` なので一意。固定した `N,M` に対して並びは200種類に限られ、任意の部分集合・順序を選べない。各セルの幅1の `in` も乱数を消費する。
2. **ABC300-A：構造の制限。** `AnswerIndex in 1..=N` とし、`C[i]=(A+B+i-AnswerIndex+1999)%2000+1` を幅1の範囲で初期化する。添字差の絶対値は299以下なので剰余の被除数は非負。長さ300以下の循環連番は重複せず、指定位置だけ `A+B`。規模や正解位置ではなく、誤答候補の組と順序が限定される。
3. **ABC355-D：検証用の規模制限。** `N≤64` は検証時間のためで、重複なし・順列・合計制約の不足ではない。端点の公式値域は既に使える。ただし公式最大 `N=500000` では整数スカラーと端点だけで1,000,001整数・出力トークンとなり、現行の各1,000,000上限を超える。高度な抽選だけで公式最大まで扱えるとはしない。
4. **ABC385-E：構造と規模の制限。** `Parent[i] in 1..=i`、`Child[i] in (i+1)..=(i+1)`。小さい番号側へたどれば頂点1に着くため木になる。頂点1を根とする増加ラベルの木に限定され、辺順も子番号の昇順。`N≤128` は検証時間のため。順列で頂点ラベルを置き換えれば全てのラベル付き木を生成対象に含められるが、その分布は一様な木にはならない。
5. **ABC420-E：構造と規模の制限。** `N in 2..=65`、`Q in 1..=(N-1)`。種類1なら `U[i] in 1..=i`、`V[i]=i+1`。大きい端点が再登場せず、既存頂点へ新頂点をつなぐ辺だけなので閉路がない。種類2・3は `V[i] in 1..=N`。Phase 6-C で種別の順序制限は解消済みだが、`N=1`、`Q≥N`、閉路は生成しない。
6. **ABC482-G：構造と総和の制限。** `MaxN=15`、`MaxM=105`、`N[t] in 2..=15`、`M[t] in 1..=N[t]*(N[t]-1)/2`。`A_i in 1..=N[t]-1` から `sum(A)≤210`。したがって `Σ(sum(A)^3)≤10*210^3=92610000≤125000000`、`ΣM≤1050`。辺 `(u,v)` は `v=2..N`、`u=1..v-1` の順に並べ、番号 `(v-1)*(v-2)/2+u` で格納。`First[t]` から連続する `M[t]` 辺しか選ばず、任意の辺集合は生成しない。ケースごとの固定幅区画に未使用セルを残すこと自体は現行仕様内。

ABC355-D の規模と他の5問の構造上の制限を混同しない。また、restricted の解消はメタデータ・生成器を実際に更新して検証した後の判断であり、本設計だけでは分類を変更しない。

## 2. 実装から引き継ぐ契約

### 2.1 宣言・初期化・出力

- 宣言は `generate` のトップレベルだけ。整数配列は `Vec<Option<i64>>` で保持し、宣言時は全セルが未初期化。整数の `=`、整数配列の一括初期化・上書き・シャッフル・集計関数は現在ない。
- `A[N] in range` は、宣言済み配列の添字 `N` の**1セル**を初期化する。長さと一致しても配列全体にはならない。対象の添字・境界・二重初期化を検査してから右辺を評価する。
- 式と範囲はソース順、左右順に評価し、ループは昇順。条件を選ぶための依存関係解析・再配置はない。未選択の分岐も静的検証するが、実行時の式評価と抽選は行わない。
- `input` は生成済みの値を読み取る。既存の条件、添字参照、`row` だけで並べ替え後の参照順を記述できる。`input` に抽選や書き換えを追加しない。
- 全体出力には全セルの初期化が必要。未出力・未参照のセルは未初期化のままでよい。DSL エラー時に CLI が部分的な標準出力を書かない構造を維持する。

### 2.2 乱数と互換性

[Generator の `SplitMix64::sample`](../src/generator.rs) は、64ビット語の剰余の偏りを棄却で除く。幅1でも1語を消費し、幅 `2^64` の全 `i64` 範囲も扱う。整数範囲と文字集合は同じ抽選器を使う。文字の固定初期化 `=`、宣言、式、条件、出力は乱数を消費しない。

新機能でも、**抽選器の呼び出し回数と、内部で消費する64ビット語数を区別する**。棄却があれば1回の呼び出しで複数語を使う。旧構文の処理・抽選器・文字候補の順序を変更せず、新操作を実行した位置にだけ乱数消費を追加する。旧ソースは同じ seed で同じバイト列を維持する。新しい構文への書き換え前後の出力一致は要求しない。

本書で「一様」という場合は、抽選器に独立一様な語が与えられるモデルでの分布を指す。固定 seed は決定的であり、有限の64ビット seed 全体から、任意の大きさの順列・組合せ全体に厳密に等確率で対応するという保証ではない。

### 2.3 上限

現行の整数配列は個別・総容量が各1,000,000、生成整数数も1,000,000。文字容量は別枠で1,000,000。ループは進入ごとに1,000,000反復、出力は1,000,000トークン・8 MiB。深さは制御32段、式128段。累積実行量10,000,000単位は、現在はネストまたは条件等を使う拡張ブロックに適用される。新操作の内部ループを、文1個として無制限に実行させてはならない。

以下の7候補を具体的に比較する。U2・B1・B2・C2・C3の構文は比較用であり、初回実装には含めない。C1は現行言語だけで書ける方法である。

| ID | 構文・方法 | 判断 |
| --- | --- | --- |
| U1 | `A in unique(l..=u) except(...)` | **最初の実装として推奨**。宣言済み整数配列を一括で単一初期化。 |
| U2 | `A[i] in l..=u except(A[1..i])` | 要素単位の対案。除外位置だけに範囲参照を追加する。柔軟だが繰り返し走査と境界の記述が増える。 |
| B1 | `shuffle A` | 不採用。初期化済みセルの値を変更する例外が必要。 |
| B2 | `B in shuffled(A)` | 将来候補。既存配列を保存し、未初期化の別配列を一括初期化。 |
| C1 | 累積配列で残り予算を表し、既存の `if` と範囲で生成 | 現行で可能。まず生成方針として利用できる。 |
| C2 | 純粋な `min` / `max` と、必要なら `sum(A)` | 記述短縮の候補。抽選機能とは分離して判断。 |
| C3 | `A in bounded_sum(l..=u, L..=U)` | 将来候補。合計範囲から総量を選び、実現可能範囲を使って逐次初期化。 |

順列専用の `permutation(...)` は U1 の全域抽選と重なるため追加しない。状態付きの pool 型は、寿命・枯渇・ケースごとの再生成を規定する別の型が必要になるため、今回の詳細候補から外す。汎用関数定義、制約ソルバー、全体の再試行、外部依存も導入しない。

## 4. A：重複なし抽選と将来の一括初期化

### 4.1 U1 と U2 の意味の違い

U1は、整数範囲から除外値を取り去った集合を `D`、その大きさを `m`、対象長を `k` とし、異なる `k` 個を**順序付きで**選ぶ。昇順に整列した結果を返す操作ではない。各列の確率は `1/(m*(m-1)*...*(m-k+1))`。順序を無視すれば各 `k` 要素集合も等確率になる。

U2は、1セルの初期化直前に明示した除外参照を評価し、残った値から1個を選ぶ。比較用の意味論は、残り候補を毎回昇順に並べ、既存サンプラーでその添字を1回選ぶものとする。幅1でも抽選を省略せず、対象検査・範囲と除外の評価は抽選前に行う。`A[1..i]` は1始まりの半開区間で、第1〜第 `i-1` セルを指す。`i=1` は空であり、未初期化セルを読まない。一般の配列長0を認める変更とは分ける。範囲の端は `1..=length+1` 内、逆転した区間はエラーとし、範囲内の全セルは初期化済みを要求する。U2でも、固定範囲から既生成の全要素を順次除外すれば順序付き標本は一様。ただし、範囲が途中で変わる一般の場合の列全体の一様性は保証しない。

U1の `except` の引数は整数式または整数配列名の列とする。整数式は初期化済みセル参照も含む。配列引数は全セルを添字順に読む。重複した除外値は1個に正規化し、範囲外の値は無視する。ただし、範囲外かを知るための式評価・初期化検査は省略しない。例えば `except(7, 7, 1000)` は範囲 `1..=9` から7だけを除く。全要素が未初期化であるべき対象自身を除外引数にすることは認めない。

両案とも値域不足は抽選前のエラー。重複した値が出るたびに引き直す実装は、充填率が高いと遅くなり、枯渇時に終了しないので採らない。U2の除外範囲を後で読むたびに取り直す素朴な実装は、長さ `k` で合計 `Θ(k^2)` セルを読む。これを避けるキャッシュは、可変値域や複数の参照区間との整合性が必要になる。

### 4.2 アルゴリズムの比較

`W` は元の範囲幅、`e` は正規化前に読んだ除外値数、`k` は生成数とする。

| アルゴリズム | 分布・計算量 | メモリ・上限 | 採否 |
| --- | --- | --- | --- |
| 値を引き、既出なら再試行 | 理想的な抽選なら一様。除外なしでも期待抽選数は `Σ W/(W-j)`、最悪時間に有限の保証がない。 | 既出集合 `O(k+e)`。値域不足を事前に数える仕組みは別途必要。 | 不採用。既存サンプラーの語の棄却と、この「値の重複による再試行」は別物。 |
| 全候補の昇順列＋部分 Fisher–Yates | 一様。除外をソートして併合走査すれば `O(e log(e+1)+W+k)`。抽選器をちょうど `k` 回呼ぶ。 | `O(W+e)`。初版の `W,e≤1000000`。候補・除外用の `i64` 列のペイロード合計は最大16,000,000バイト。 | **初版で採用**。対象コーパスの200、2000、最大候補辺124750を十分扱える。 |
| 疎な部分 Fisher–Yates | 仮想候補列の交換位置だけを管理。平衡木なら `O(e log(e+1)+k log(k+1)+k log(e+1))`。 | `O(k+e)`。`W=2^64` も幅を広い型で保持できる。ノードの実メモリは密な列より大きい。 | 将来の値域上限緩和案。昇順の除外後候補に同じ交換を定義すれば、初版と同じ抽選結果を維持できる。 |
| 全候補を全てシャッフルして先頭 `k` 個 | 一様だが `k≪W` でも `W-1` 回の抽選。 | `O(W)`。 | U1には過剰。既存配列全体の B2 では適切。 |

疎な方式では、ソート・重複除去済みの除外オフセットを `x_i`（0始まり）とする。除外後の順位 `r` は `r + count(x_i-i≤r)` で元のオフセットへ戻せるので、値域全体を走査する必要はない。交換位置をハッシュ表で実装する場合も、その反復順を候補順や乱数順に使ってはならない。初版ではこの仕組み自体を実装しない。

### 4.3 `A[N] in ...` 構想との関係

現行の `A[N] in 1..=9` は1セルの初期化である。一括初期化への読み替えや、「`N` が長さと同じなら全体」という規則は採用しない。特に以下の既存コードの意味を保つ。

```text
A[N]
A[N] in 1..=9
```

U1は宣言後に `A in unique(...)` と書く。将来、独立な通常抽選の一括初期化を追加するなら、`A in 1..=9` のような別の初期化文を同じ内部処理へ接続できる。独立抽選の一括処理は、添字1から長さまで既存の要素初期化を行う順序と同じに定義できる。

未宣言の名前に限って `A[N] in ...` を「宣言＋一括初期化」の糖衣構文にする案は、現在その位置が未宣言配列のエラーになるため、既存の成功例とは衝突しない。しかし同じ見た目が名前の宣言状態によって変わり、Parser の現在の「添字＋初期化」という分類とも異なる。**今回は導入しない**。将来採用する場合も、トップレベルの新規宣言だけに限定して U1 等へ展開し、宣言済み配列の添字形は必ず1セルのままとする。まず二段階の形を問題文から自動生成する方が、宣言長と添字を取り違えにくい。

## 5. 対象4問の U1・U2 記述例

この節の U1 は完成した生成器の提案例、U2 は同じ生成器の該当部分を置き換える断片である。コメント、疑似関数、未定義の省略記号を実行可能な DSL として扱わない。既存コーパスのファイルには反映しない。

### 5.1 ABC355-B：2配列をまたぐ一意性

**U1：**

```text
generate {
    N in 1..=100
    M in 1..=100
    A[N]
    B[M]
    A in unique(1..=200)
    B in unique(1..=200) except(A)
}
input {
    N M
    A
    B
}
```

`N+M≤200` なので不足しない。固定した `N,M` のもとで、相異なる全ての順序付き `A,B` を等確率で扱う。各配列を別々に `unique` で作るだけでは、配列間の重複を防げない。

**U2：** 宣言後の2ループを次に置き換える。

```text
for i in 1..=N {
    A[i] in 1..=200 except(A[1..i])
}
for i in 1..=M {
    B[i] in 1..=200 except(A, B[1..i])
}
```

同じ生成対象を一様に扱えるが、除外する既生成セルを毎回指定し、繰り返し読む。U1とU2は候補の更新順が異なるので同じ seed の出力一致は要求しない。

### 5.2 ABC300-A：既知の正解を除外してから1か所に置く

**U1：**

```text
generate {
    N in 1..=300
    A in 1..=1000
    B in 1..=1000
    AnswerIndex in 1..=N
    Distractors[N]
    C[N]
    Distractors in unique(1..=2000) except(A+B)
    for i in 1..=N {
        if i == AnswerIndex {
            C[i] in (A+B)..=(A+B)
        } else {
            C[i] in Distractors[i]..=Distractors[i]
        }
    }
}
input {
    N A B
    C
}
```

長さ0の配列を導入せず `N=1` も扱うため、誤答候補を `N` 個選び、正解位置の1個を使わない。実際に必要な `N-1` 個の周辺分布は一様である。`A+B` は `2..=2000`、残り1999候補に対して `N≤300` なので不足しない。`C` は各セルを1回だけ初期化する。整数のコピーにも幅1の抽選がある点は現行どおり。

固定した `N,A,B` に対して、正解を1個含む全ての有効な `C` の列を一様に扱える。`A,B` の抽選により `A+B` 自体の分布は中央ほど多くなるので、入力全体を値域の全組から一様に選ぶ主張はしない。

**U2：** `Distractors` をなくし、`C` のループを次にする。

```text
for i in 1..=N {
    if i == AnswerIndex {
        C[i] in (A+B)..=(A+B)
    } else {
        C[i] in 1..=2000 except(A+B, C[1..i])
    }
}
```

正解が既に接頭辞にあっても、重複した除外値は1個として数える。U2はこの例では記述と一時配列を減らせるが、範囲参照の新設が必要になる。

### 5.3 ABC385-E：親を生成してから頂点ラベルを置換

**U1：**

```text
generate {
    N in 3..=128
    P[N]
    Parent[N-1]
    P in unique(1..=N)
    for i in 1..N {
        Parent[i] in 1..=i
    }
}
input {
    N
    for i in 1..N {
        if P[Parent[i]] < P[i+1] {
            P[Parent[i]] P[i+1]
        } else {
            P[i+1] P[Parent[i]]
        }
    }
}
```

`P` は `1..=N` の順列。木の同型性を保ったままラベルを変え、出力側の比較で `u<v` を保証する。出力側の比較・参照は読み取り専用である。全てのラベル付き木に到達できるが、増加ラベルの木を作ってから置換する分布なので、木全体は一様ではない。辺順もまだ内部の子番号順であり、任意順序ではない。

追加で `Order[N-1]` を `unique(1..=N-1)` で初期化すれば、出力参照の `i` を `Order[i]` に置き換えて辺順も抽選できる。最初の例では `P` と `Parent` の計 `2N-1` セルだけでよく、辺順も持つ場合は `3N-2` セル。公式最大 `N=300000` でもそれぞれ599999・899998セル、出力は599999トークンであり、現行上限内に収まる。実行時間を測らず現在の規模設定を自動的に増やすものではない。

**U2：** `P in unique(...)` を次に置き換える。以後の親生成・出力は同じ。

```text
for i in 1..=N {
    P[i] in 1..=N except(P[1..i])
}
```

素朴な接頭辞走査は `Θ(N^2)` になり、公式上限を目指す用途では U1 より不利。

### 5.4 ABC482-G：辺番号を重複なしで選ぶ

**U1：初回機能だけで書ける単一ケースのプロファイル。** 任意の単純グラフの辺集合に到達する例であり、ケース間総和の解決例とは分ける。

```text
generate {
    T in 1..=1
    N in 2..=500
    K in (N*(N-1)/2)..=(N*(N-1)/2)
    M in 1..=K
    A[N]
    U[K]
    V[K]
    Edge[M]
    Edge in unique(1..=K)
    for i in 1..=N {
        A[i] in 1..=1
    }
    for v in 2..=N {
        for u in 1..v {
            U[(v-1)*(v-2)/2+u] in u..=u
            V[(v-1)*(v-2)/2+u] in v..=v
        }
    }
}
input {
    T
    N M
    A
    for i in 1..=M {
        U[Edge[i]] V[Edge[i]]
    }
}
```

`K≤124750`。固定した `N,M` に対して全ての単純グラフの辺集合とその行順が一様。`sum(A)=N≤500`、`T=1` なので立方和制約を満たし、`M≤124750<200000`。最大配列容量は `N+2K+M≤374750`。`T=1` と `A_i=1` は新たな限定であり、現行の多ケース生成器をこの例で置き換える提案ではない。

U1の初版は配列全体だけを対象とするため、ケースごとに長さが変わる平坦配列の一部分を独立抽選する機能までは含まない。多ケースの任意の辺集合を同時に生成するには、後述の U2、将来の区間一括初期化、またはケースごとの配列を表す型が別途必要。異なるケースでも辺番号を使い回せるため、全ケースを一つの `unique` にまとめるのは誤りである。

**U2：多ケースの断片。** `Edge[200000]` と、既生成の `Off[T+1]` を用意し、`Off[1]=0`、`Off[t+1]=Off[t]+M[t]` と幅1の範囲で単一初期化する。`ΣM≤200000` の予算配分は第7節による。

```text
for i in 1..=M[t] {
    Edge[Off[t]+i] in 1..=(N[t]*(N[t]-1)/2) except(Edge[(Off[t]+1)..(Off[t]+i)])
}
```

除外は同じケースの接頭辞だけで、他ケースとの辺の一致は許す。候補端点列は最大 `N=500` の `U[124750]`,`V[124750]` を一度だけ生成し、出力を `U[Edge[Off[t]+i]] V[Edge[Off[t]+i]]` とすればよい。U2の素朴な処理は密なグラフで遅くなる。

## 6. B：順列とシャッフル

### 6.1 B1 を採らない理由と B2 の契約

`shuffle A` は、既に初期化された `A[i]` の値を変更する。後の文で同じセルを読んだ値が変わり、単一初期化から得られる値の安定性を失う。「初期化完了前だけ許す」「入力出力用の並びだけ変更する」といった例外も新しい状態・参照モデルを要するため採らない。

B2の `B in shuffled(A)` は、同じ長さの別の整数配列 `B` の全セルを初期化する。`A` は全セル初期化済み、`B` は全セル未初期化、同一配列は禁止。型・長さ・初期化状態・容量を検査してからコピーし、内部の候補列をシャッフルして `B` に一度だけ書く。既存の `A` は変わらない。コピーした整数セルも生成整数数の上限に数える設計とする。

アルゴリズムは、コピーした添字順の列に、`j=n,n-1,...,2` の順で `1..=j` を1回抽選し、その位置と `j` を交換する降順 Fisher–Yates。抽選器の呼び出しは `n-1` 回、長さ1では0回。時間 `O(n)`、追加メモリ `O(n)`、元と先の配列容量の合計も1,000,000以内。途中までしか初期化されていない配列を、初期化済み部分だけ暗黙にシャッフルしない。

各**位置の順列**が一様である。元の値に重複があっても処理できるが、一意性を新しく保証する機能ではない。合計、値の組、グラフの形も変わらない。

### 6.2 対象4問での記述

下表は既存の生成器、または第5節の提案例の該当部分へ追加する断片。B1列は不採用構文の比較用である。

| 問題 | B1の記述例（不採用） | B2の記述例・使い方 |
| --- | --- | --- |
| ABC355-B | `shuffle A` と `shuffle B` | `SA[N]`、`SB[M]` を宣言し、生成後に `SA in shuffled(A)`、`SB in shuffled(B)`。出力を `N M`、`SA`、`SB` にする。元が剰余列なら選べる集合とA/Bへの分割はそのまま。U1ならシャッフルを足さず両方を広げられる。 |
| ABC300-A | `shuffle C` | `D[N]` を宣言し、`D in shuffled(C)`、出力を `N A B` と `D` にする。正解位置を動かせるが、循環連番の誤答集合自体は広がらない。 |
| ABC385-E | `shuffle Base` | `Base[N]` にループで `Base[i] in i..=i`、別の `P[N]` に `P in shuffled(Base)`。第5.3節のラベル置換に使う。直接 `P in unique(1..=N)` と比べ、恒等列の生成・保持が増える。 |
| ABC482-G | `shuffle AllEdges` | 単一ケース例で `AllEdges[K]` に `AllEdges[e] in e..=e`、`Order[K]` に `Order in shuffled(AllEdges)`。先頭 `M` 個の `U[Order[i]] V[Order[i]]` を出力する。辺集合は広がるが、全 `K` 候補の初期化・抽選が必要。U1は `Edge[M]` だけを初期化できる。 |

順列の直接生成は **U1で対象長と候補数が一致する場合**であり、例えば `P[N]` と `P in unique(1..=N)` だけでよい。B2が必要なのは、整数の連続範囲ではない既生成値の集合、多重集合などの順序を変える場合である。

U1の全域抽選は前進する交換を `n` 回行い、最後の幅1の抽選も消費する。B2は降順で `n-1` 回。恒等列を B2 で並べ替えたものと、U1の順列は同じ分布でも、同じ seed に対して同じ列・後続乱数にはならない。この違いを最適化で勝手に消さない。

## 7. C：合計制約とケース間の予算

### 7.1 C1：累積配列だけで実現可能範囲を計算する

要素数 `n`、各要素の値域 `[l,u]`、目標合計 `S` とする。現在までの合計を `p`、現在の後に残る要素数を `r` とすれば、現在の値を次の範囲から選ぶ。

`max(l, S-p-r*u) ≤ x ≤ min(u, S-p-r*l)`

残りの要素が実現できる最小・最大合計を両側から予約する。上限だけを `min(u,残り予算)` にすると、末尾の最低値や目標下限を満たせないことがある。合計範囲 `[L,U]` の場合は、先に `[L,U]∩[n*l,n*u]` から目標 `S` を選べばよい。空なら生成方針のエラーである。

現在の DSL には `min/max` も代入可能な予算変数もないが、`if` と累積配列への1回ずつの初期化で書ける。例えば ABC482-G の1ケースの `N,S,A` は次の**現行構文だけの生成側断片**で構成できる。出力側には `N M`、`A`、既存方式の辺列を組み合わせる。

```text
N in 2..=500
Limit[1]
if N*(N-1) < 500 {
    Limit[1] in (N*(N-1))..=(N*(N-1))
} else {
    Limit[1] in 500..=500
}
S in N..=Limit[1]
A[N]
Prefix[N+1]
Low[N]
High[N]
Prefix[1] in 0..=0
for i in 1..=N {
    if S-Prefix[i]-(N-i)*(N-1) > 1 {
        Low[i] in (S-Prefix[i]-(N-i)*(N-1))..=(S-Prefix[i]-(N-i)*(N-1))
    } else {
        Low[i] in 1..=1
    }
    if S-Prefix[i]-(N-i) < N-1 {
        High[i] in (S-Prefix[i]-(N-i))..=(S-Prefix[i]-(N-i))
    } else {
        High[i] in (N-1)..=(N-1)
    }
    A[i] in Low[i]..=High[i]
    Prefix[i+1] in (Prefix[i]+A[i])..=(Prefix[i]+A[i])
}
```

`Prefix[i]` は最初の `i-1` 要素の合計。最後は下限・上限がともに残り合計になり、`Prefix[N+1]=S`。`Low`,`High`,`Prefix` も各セル1回だけ初期化する。幅1で表す中間値も乱数を消費するため、この断片では `Limit` と `S` 等の抽選に加えて、ループ内で各要素につき4回の抽選を行う。合計を守れることと、乱数を消費しない計算として記述できることは別である。

この方法は全ての実現可能な配列を生成対象に含められるが、一般には一様ではない。例えば値域 `0..=2`、長さ3、合計2では、先頭を0・1・2とする残りの完成数が3・2・1個である。それぞれの先頭を1/3で選ぶと完成した配列の確率は一致しない。完成数で重み付けする動的計画法は `O(n*S)` 規模と大きい整数の重みを要し、今回の一般機能には採用しない。

### 7.2 ABC482-G の2種類のケース間総和

以下の記号は説明用の数学的な値であり、現行 DSL の代入文ではない。`s_t=sum(A_t)`、未処理ケースを `q=T-t`、処理前の残り立方予算を `B_t`、残り辺予算を `E_t` とする。

1. `B_1=500^3`、`E_1=200000`。未処理の各ケースは最低 `N=2,s=2,M=1` を必要とするため、立方予算 `8*q`、辺予算 `q` を予約する。
2. `C_t=floor_cuberoot(B_t-8*q)` を計算する。`N[t]` を `2..=C_t` から選ぶ。
3. `s_t` を `N[t]..=min(C_t,N[t]*(N[t]-1))` から選ぶ。これなら各要素が `1..=N[t]-1` の配列として実現できる。単に `s_t≤500` とするだけでは複数ケースの立方和を保証できない。
4. `B_{t+1}=B_t-s_t*s_t*s_t` を新しい配列セルへ単一初期化する。上記の配列内予算法で正確に `s_t` を配分する。
5. `M[t]` を `1..=min(N[t]*(N[t]-1)/2,E_t-q)` から選び、`E_{t+1}=E_t-M[t]` を新セルへ単一初期化する。辺集合の一意性は、この予算管理とは別に保証する。

`N[t]` の下限と `s_t≤N[t]*(N[t]-1)` が重要であり、立方予算だけを見て大きな `s_t` を小さい `N[t]` に割り当てない。各段階で将来の最小分を予約するため、途中で実現不能な範囲にならない。中間の積・減算は検査付きで計算する。

`floor_cuberoot` を新しい DSL 関数にすることは必須ではない。`s≤500,T≤10` なので、先に宣言した `Cap[T]` に対して以下をケース `t` の本体で実行すれば、既存の比較・反復だけで上限を一度だけ初期化できる。`CubeLeft[T+1]` は残り予算を保持し、初期セルには125000000を入れる。

```text
for x in 2..=500 {
    if x*x*x <= CubeLeft[t]-8*(T-t) {
        if (x+1)*(x+1)*(x+1) > CubeLeft[t]-8*(T-t) {
            Cap[t] in x..=x
        }
    }
}
```

立方が狭義増加するため該当する `x` は一つ。最大4990反復で、値域に固定上限があるこの問題では十分小さい。`N[t]`、`s_t`、`M[t]` の上限の `min` も第7.1節と同じ分岐で書ける。汎用の立方根や非線形制約ソルバーは不要。

保存領域は、`A[T*500]` のケース別区画、ケースごとの累積配列、最大頂点数の候補端点 `U[124750],V[124750]` を共有する構成でよい。辺を現行と同じ連続区間から選ぶなら、その `First[t]` と `M[t]` だけを保存する。任意辺集合なら第5.4節の `Edge[200000]` と `Off` を加える。概算でも5000+249500+200000セルと小規模な予算配列で、総容量1,000,000以内。`ΣM≤200000` から出力トークン数も最大 `1+2T+500T+2*200000≤405021`、値は500以下なので8 MiB以内に収まる。

### 7.3 上限近くを狙うプロファイル

- **配列内合計500：** `T=1,N=25,S=500` を幅1の範囲で固定する。`25≤500≤25*24` なので多様な `A` に配分でき、立方和は `500^3` に等しい。`N=500,A_i=1` でも同じ境界だが、配列の値は固定になる。
- **立方和の上限近傍：** 第7.2節で各 `s_t` を許される上限に寄せる。後続ケース分の予約を残す。立方数の間隔があるので、常に総和を正確に125000000へ一致させられるとはしない。
- **辺数総和200000：** 先に全ケースの `N[t]` と `s_t` を決め、候補辺数 `K_t=N[t]*(N[t]-1)/2` を累積する。`ΣK_t≥200000` のとき、目標辺総量200000を、各値域 `1..=K_t` に対する実現可能範囲で配る。残りケースの最大容量も予約する下限 `max(1,残量-残りのΣK)` が必要であり、最小1ずつの予約だけでは境界到達を保証しない。
- **具体的に両方が厳しい有効例：** `T=5`、各 `N=292,A_i=1,M=40000`。各候補辺数42486、`ΣM=200000`、`Σ(sum(A)^3)=5*292^3=124485440≤125000000`。現行の連続区間の辺選択でも有効に構成できる。任意の辺集合への拡大には重複なし抽選を組み合わせる。

通常のランダムプロファイルだけで最大値が現れることを期待せず、境界用の目標を生成側に明示する。これらの固定値はテスト設計の例であり、今回コーパスへ追加しない。

### 7.4 C2・C3 と集計関数の必要性

C2の `min/max` は純粋な整数式であり、乱数を消費しない。第7.1節の `Low`,`High` とその分岐をなくせる。

```text
A[i] in max(1,S-Prefix[i]-(N-i)*(N-1))..=min(N-1,S-Prefix[i]-(N-i))
Prefix[i+1] in (Prefix[i]+A[i])..=(Prefix[i]+A[i])
```

これは**未実装の純粋関数を使う候補**。`min/max` は引数2個、左から右に評価、`Int` のみ、結果も `Int` とする案。`Prefix` の幅1の抽選はなお残る。新関数を足すなら、関数名の後ろの `(` で認識し、既存の同名変数を予約語で壊さない。

`sum(A)` は既に完成した配列の合計を知るためには便利だが、これだけで初期化途中の予算制約を守れない。途中の未初期化セルを暗黙に0と扱ってはならない。採用するなら全セル初期化済みを要求し、添字順の検査付き加算、乱数消費なし、読み取り `O(n)` を実行量に計上する。ループのたびに配列全体を `sum` すれば `O(n^2)` になる。平坦化した多ケース配列の一部を集計するには範囲参照等も必要である。

このコーパスでは、先に選んだ目標 `s_t` と末尾の累積値が同じなので、**配列集計関数は必須ではない**。立方和はその `s_t` から予算配列に計上できる。自動生成でも、予算制約から目標総量を先に構成する方が、生成後の `sum` と全体の再抽選を繰り返すより扱いやすい。

C3は、次の一括初期化を候補とする。`S` を別に指定するなら `S..=S` と書く。

```text
A[N]
A in bounded_sum(1..=(N-1), N..=500)
```

値域・合計範囲を左から右へ1回評価し、実現可能な合計範囲と交差させる。その中から合計を1回抽選し、第7.1節の両側の予約を使って添字順に `N` 回抽選する。幅1の合計と最後の強制要素も抽選を消費し、計 `N+1` 回。整数セルは `N` 個として計数し、内部の目標合計は保存されない作業値とする。対象は全セル未初期化の整数配列のみ、時間 `O(N)`、対象以外の作業メモリ `O(1)`。中間の要素数×端点は `i128` で計算し、指定合計と最終合計は `i64` 内に限定する。

この意味では合計値は一様に選べるが、配列全体は一様ではない。固定合計についても第7.1節の偏りが残る。ケース間の非線形な総和は C3 だけでは解決せず、前段の予算配分が必要。また、初版の全配列対象という形だけでは、平坦配列のケース別区画をそれぞれ C3 で初期化できない。区間対象を別途設計せず、動的ケースへの適用まで完了した扱いにはしない。

## 9. 最初の機能の構文案と実行契約

**推奨範囲は U1 だけ。** 配列の宣言と除外付き一括抽選を実装し、要素への除外、シャッフル、集計、合計専用構文、区間一括初期化、宣言と初期化の糖衣構文は同時に実装しない。

### 9.1 文法案

現行の `generate-line` に以下の選択肢を足す設計。下位の `name`、`expression`、`range` と改行規則は現行のものを使う。`unique` と `except` はこの形だけで認識する文脈キーワードであり、一般の関数機構ではない。

```ebnf
whole-unique-init = name, "in", "unique", "(", range, ")",
                    [ "except", "(", exclusion, { ",", exclusion }, ")" ], line-end ;
exclusion         = expression ;
```

`exclusion` の裸の名前が整数配列を指す場合だけ、除外用の配列引数として束縛する。それ以外は現行の整数式として検証する。例えば `except(B, A+B, C[1])` は配列と整数式の混在、`except(B+1)` はBが配列なら型エラー。裸の配列が通常の算術式として有効になる変更ではない。`except()` は構文エラーとし、引数なしなら節ごと省略する。

初版は `generate` のトップレベルのみ。名前の新規宣言ではなく、先に宣言された整数配列を対象にする文で、名前の登録数・可視範囲は増えない。`input`、制御本体、文字列・文字列配列・スカラーを対象とした使用は拒否する。宣言は従来どおりトップレベルに置き、将来の制御本体対応も別判断とする。

### 9.2 評価・抽選・書込みの順序

1. 対象配列の全セルが未初期化であることを添字順に確認する。1セルでも初期化済みなら、残りだけ埋めることはせず二重初期化エラー。右辺の評価や抽選より先に検査する。
2. 範囲の下限、上限を1回ずつ評価する。幅は `i128` で計算し、空範囲を拒否する。初版は**除外前の幅 `W≤1000000`** を要求する。幅が大きく、除外後に少数だけ残る場合も対象外である。
3. `except` の各引数を左から右へ、配列は添字順に評価する。読んだ整数数 `e≤1000000` を要求し、重複・範囲外の値も読み取り数に含める。未初期化の配列引数は最初の該当セルをエラーにする。
4. 除外値をソート・重複除去し、範囲内の除外数から残り候補数 `m` を確定する。対象長 `k>m` なら値域不足。生成整数数の残量 `k`、内部処理の実行量、必要な作業容量も抽選前に確認する。エラー時に乱数を消費しない。
5. 除外後の候補を値の昇順に並べる。`j=1..k` の順で、既存サンプラーから添字 `j..=m` を1回ずつ抽選し、候補列のその位置と `j` を交換する。区間長1でも省略しない。
6. 候補列の先頭 `k` 個を `A[1]..A[k]` に各1回書く。生成整数数へ `k` を計上する。候補の列挙・除外値の読み取り・内部の添字抽選は、保存される生成整数数には数えない。

候補列を内部で変更することは、公開済みのDSL配列セルを再代入することではない。対象への書込みは全検証・候補抽選後に行う。以後は通常の整数配列と同じ読み取り・再初期化禁止の規則が適用される。

候補の列挙はオフセットを広い型で計算し、`i64::MAX+1` を狭い型で作らない。例えば `9223372036854775806..=9223372036854775807` の2値抽選も有効。全 `i64` 範囲は既存の通常抽選では有効なままだが、新しい U1 初版では候補幅上限エラーになる。この制限を汎用の `in range` へ波及させない。

### 9.3 実行量・メモリ・診断

新操作を含む `generate` ブロックにも、既存の累積実行量10,000,000を有効にする。旧ソースへの適用条件は変えない。新文の既存の文1単位に加えて、次を論理的な内部作業単位として計上する案とする。

`k + W + e * ceil(log2(e+1))`

これは対象検査・候補走査・除外値の読取りとソート・抽選の規模を束縛するための、決定的な課金式であり、CPU命令数の厳密な上限ではない。加算・積は広い型で事前検査する。`e=0` の項は0。入力例の最大候補辺列124750や順列300000を無理なく扱える一方、除外が極端に多い場合は容量以内でも実行量で拒否し得る。課金は抽選前に確定させる。

候補列・除外列のペイロード上限は合計16,000,000バイト。対象の `Vec<Option<i64>>`、配列管理、整形済み出力、アロケータの管理領域は別であり、これをプロセス全体のメモリ上限と呼ばない。必要な容量を検証し、抽選前に確保する。候補列自体を結果の作業領域として使い、さらに長さ `k` の結果列を重ねて確保しない。

| 失敗 | 診断位置・内容 |
| --- | --- |
| 未宣言・型違い・制御本体内の使用 | 対象名または新構文の位置。配列初期化文であることを示す。 |
| 二重初期化 | 対象名。最初の初期化済み添字を付記。 |
| 除外配列の未初期化 | 引数の参照位置。最初の未初期化添字を付記。 |
| 空範囲・端点の算術失敗 | 現行の範囲・式の診断規則を踏襲。 |
| 値域不足 | `unique` の位置。必要数 `k`、範囲幅 `W`、範囲内の異なる除外数、利用可能数 `m` を示す。 |
| 候補幅上限 | 範囲の位置。値域不足とは区別し、初版の候補幅上限であることを示す。 |
| 除外読取り数・生成整数数・実行量超過 | 原因となる引数または初期化文の位置と上限を示す。 |

本体を実行しない分岐では抽選しないという将来の一般化も可能だが、初版では制御本体内のU1自体を構文段階で拒否する。旧整数・文字列の乱数消費とエラー処理を共有して変更する必要はない。

## 10. 後続実装の計画と完了条件

以下は次フェーズで行う計画であり、今回実施する変更ではない。

1. **契約と互換性の基準を固定する。** 本書の構文、候補の昇順、前進する交換、最後の幅1抽選、除外の正規化、各上限をレビューする。実装前の現行10生成器について共通14 seed、既存の境界seed・グリッド固定寸法の出力を比較用に保存する。
2. **Parser / AST。** `WholeUniqueInit` 相当の生成文と、範囲・除外引数・各診断位置を追加する。`name in unique(` だけを新文として認識し、従来の `unique` というスカラー名や変数参照を壊さない。添字付きの行と整数・文字の既存初期化文はそのままにする。制御本体には新文を通さない。
3. **Validator。** 新文を宣言として登録せず、対象を既存整数配列へ束縛する。除外引数を整数式と全整数配列に解決し、宣言順・型・自己参照禁止を検査する。配列全体を一般の整数式に昇格させない。
4. **Generator。** 新文専用に、対象状態検査、範囲・除外の評価、容量・作業量・必要整数数の検査、昇順候補列、部分Fisher–Yates、単一書込みを追加する。整数・文字が使う既存サンプラーをそのまま呼ぶ。依存クレートは追加しない。
5. **将来実装時の検証。** 最小長・全域選択・負の範囲・半開/閉区間・`i64` 端付近、範囲内外と重複した除外、整数式と配列の混在、候補不足、部分初期化対象、未初期化除外、各上限の直前/一致/超過、後半でエラーになったCLIの出力0バイトを確認する。抽選順は小さい候補列を使った既知のseed結果と、直後の通常整数・文字抽選まで比較する。有限seedの頻度検査だけを一様性の証明にはせず、各段階で残り候補から等確率に選ぶ構成で説明する。
6. **既存結果の互換性を確認する。** 既存の単体・CLI・コーパス検証を実施し、変更前の出力とバイト比較する。特に幅1、棄却が起きる範囲、全 `i64` 範囲、文字の候補順、固定文字、未選択分岐を確認する。これらは既存の回帰検査にも例がある。
7. **その後に生成器を評価する。** まず ABC355-B と ABC300-A を別の変更として拡張し、既存チェッカーで公式制約を確認する。ABC385-E のラベル置換・辺順、ABC482-G の単一ケース任意辺集合も追加プロファイルとして評価する。多ケース総和は C1 の構成を先に確認し、区間抽選等の必要性を測ってから次機能を選ぶ。
