# atcgen

AtCoder の Stress Test 用に、入力形式を表す DSL と seed からテストケースを 1 件生成する Rust CLI です。

## 実行例

リポジトリのルートから実行します。

```sh
cargo run --quiet -- generate sample.gen --seed 42
```

下記の DSL を `sample.gen` に記述した場合の出力です。

```text
4
83 90
46 99
43 72
69 99
```

ビルド済みの CLI は `atcgen generate sample.gen --seed 42` で実行できます。`--seed` には符号なし 64 ビット整数を指定します。成功時の標準出力は生成した入力のみです。エラーは標準エラー出力に出し、非ゼロで終了します。DSL エラーにはファイル名、行番号、列番号を表示します。

## DSL

```text
input {
    N
    for i in 1..=N {
        A B
    }
}

constraints {
    N in 1..=10
    A in 1..=99
    B in (A+1)..=100
}
```

- UTF-8 のファイルで `input {`、`constraints {` の順に記述します。ブロックの開始と終了はそれぞれ独立した行に記述します。空行、字下げ、LF と CRLF を使用できます。
- 変数名は `[A-Za-z_][A-Za-z0-9_]*` で、大文字と小文字を区別します。`for` は予約語です。同じスコープには同じ名前を一度だけ宣言できます。
- `input` の宣言行ごとに 1 行を出力します。同じ行の宣言を空白で区切ります。`N` は整数を 1 個生成します。配列は `A[N]` のように長さを指定し、`A[N-1]` や `A[(N+M)*2]` のような整数式も使えます。配列長は正の整数に限ります。空配列は未対応です。各行の整数は半角スペース 1 個で区切り、最終行も LF で終わります。
- `constraints` は 1 行に 1 件です。スカラー、配列、ループ内の宣言に共通して `A in 1..=100` の形式を使います。配列なら全要素に、ループ内の宣言ならすべての反復に適用します。生成変数名ごとに制約が 1 件必要です。
- 生成順は `input` の上から下、同じ行では左から右です。各変数の生成直前に制約範囲を評価します。配列の場合は長さも評価し、各要素を同じ範囲から生成します。制約の記述順は自由です。

## `for` とスコープ

`for i in 1..=N {` で始まるブロックの各行を、反復ごとに出力します。ループ開始時に範囲を 1 回評価し、開始値から昇順に 1 ずつ進みます。ループ変数 `i` は本体内で参照でき、出力や生成制約の対象にはなりません。空の範囲では 0 回反復します。本体内の空行は反復ごとに空行として出力し、トップレベルの空行は整形用として扱います。

サンプルでは反復ごとに新しい `A` を生成し、その反復の `A` を使って `B` の範囲を評価します。`B in (A+1)..=100` により、すべての反復で `A < B` になります。ループ内では生成済みの外側のスカラーと、同じ反復ですでに生成したスカラーを参照できます。前の反復の値、後続の宣言、ループの外や別のループにあるローカル変数は参照できません。ループ範囲の式はループ開始前の外側のスコープで評価します。

`A[N]` は長さ `N` の配列を 1 行に出力します。`for i in 1..=N` の本体の `A` は反復ごとに 1 個を生成し、合わせて `N` 行に出力します。配列や反復で得た値は、内部では生成順にコレクションとして保持します。配列やループ終了後のコレクションをスカラーとして参照するとエラーになります。

ループ内外の生成変数名の衝突と、ループ変数名と生成変数名の衝突は禁止です。別々のループでは同じ名前を宣言できます。その場合、制約を共有し、各宣言のスコープで式の参照先を解決します。

## 範囲記法

開始値は常に含みます。`a..b` は終端 `b` を含まず、`a..=b` は終端 `b` を含みます。たとえば `1..10` は 1〜9、`1..=10` は 1〜10、`5..=5` は 5 のみです。`1..1` や `6..=5` は空範囲で、生成制約ではエラーになります。`...` は構文エラーになります。

旧記法から移行する際は、配列要素の制約 `A[*] in ...` を `A in ...` に書き換えてください。旧記法は構文エラーになります。Phase 2 以前の両端包含の範囲は `a..=b`、旧配列宣言 `A[1..N]` は `A[N]` に書き換えてください。同じ生成範囲・配列長・行構成を指定すれば、同じ seed で従来と同じ出力になります。

## 整数式

配列長と、ループ・制約範囲の上下限に整数式を指定できます。整数リテラルは十進表記の符号付き 64 ビット整数（`i64`）です。式からはスコープ内の生成済みスカラーと、現在のループ変数を参照できます。未定義変数、前方参照、自己参照、配列の参照はエラーになります。

| 優先順位（高い順） | 記法 | 意味 |
| --- | --- | --- |
| 1 | `(A+B)` | 括弧内をひとまとまりとして扱う |
| 2 | `-A`、`+A` | 符号反転、値をそのまま返す |
| 3 | `A*B`、`A/B`、`A%B` | 乗算、整数除算、剰余 |
| 4 | `A+B`、`A-B` | 加算、減算 |

同じ優先順位の二項演算子は左結合です。`20-6-3` は `(20-6)-3` と同じです。除算はゼロ方向に切り捨て、剰余は Rust と同じ規則に従います。たとえば `-7/3` は `-2`、`-7%3` は `-1` です。括弧と単項演算子の入れ子は合わせて 128 段までです。負の整数リテラルの符号はこの段数から除きます。

括弧の不一致や未対応の演算子は構文エラーです。ゼロによる除算・剰余、途中の計算を含む整数オーバーフロー、空の生成範囲、0 以下の配列長もエラーになります。`i64` の最小値を `-1` で除算する場合と剰余を取る場合も、Rust と同様にオーバーフローとして扱います。算術エラーは式と該当する演算子の位置を表示します。生成途中でエラーになった場合は標準出力が空のまま終了します。

## 乱数と上限

SplitMix64 の初期状態に `seed` をそのまま設定します。各整数を生成するたびに 64 ビットの乱数を取得します。範囲に含まれる整数の個数を `w` とし、乱数が `2^64 mod w` 未満なら取り直して、`下端 + 乱数 mod w` を採用します。`i64` の全範囲を指定した場合は乱数をそのまま下端からのオフセットに使います。この手順で同じ DSL と seed から同じバイト列を生成します。

1 ケースの上限は整数 1,000,000 個、出力 8 MiB です。出力サイズには空白と改行を含みます。各ループの反復回数も 1,000,000 回までです。上限を超えた場合は生成結果を出力せずエラーを返します。

## 未対応の機能

ネストした `for`、`constraints` 内の `for`、`A[i]` のような要素参照、文字列、行列、`distinct` / `sorted`、比較・論理演算、グラフ生成、問題文の自動解析、`atc-rs` との統合は未対応です。
